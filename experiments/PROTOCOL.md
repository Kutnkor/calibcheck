# Experiment protocol (declared before execution)

Written 2026-10-18, before running `experiments/run_experiments.py`. Results go to
`experiments/results/`, and that directory is generated by the script only. Nothing in it is edited by hand.

## Question

On held-out test rows, how do the shipped recalibration methods (`sigmoid` = logit-affine
sigmoid, `isotonic`, `temperature`) change the probability quality of a fixed base model?
How does that vary across data-generating situations and random splits? This is a
descriptive study of CalibCheck's implemented methods. It does not claim that any method is
generally better.

## Primary metric

The primary metric is the **test-set Brier loss difference, method − raw**, on identical test rows. Negative values favour the
method. Secondary metrics are the test log-loss difference and the test binned positive-class ECE
(uniform, 10 bins). Each method is fitted on calibration rows only and never sees test outcomes.

## Study A — synthetic recalibration (known mechanism)

* Scenarios: `calibrated`, `near_calibrated`, `overconfident`, `underconfident`,
  `intercept_bias`, `imbalanced`, `headline`.
* n = 4000 per run (`headline`: 6000). The generator's own random split puts 50% in
  calibration and 50% in test.
* Seeds 1–20 for every scenario. That gives 7 scenarios × 20 seeds = 140 runs, and each run fits 3 methods.

## Study B — base predictors with train / calibration / test roles

* Base predictors: a constant predictor (training prevalence), logistic regression
  (StandardScaler + LogisticRegression, max_iter 2000), and a random forest (300 trees,
  min_samples_leaf 1). The random forest is chosen because its raw probabilities are often poorly calibrated.
  Preprocessing is fitted on training rows only, inside a scikit-learn Pipeline.
* Roles: stratified split into 50% train, 25% calibration and 25% test, re-drawn for each seed. No
  method selection is performed on test rows. Every predeclared method is reported (exploratory mode).
* Datasets:
  1. `synthetic_tabular`: scikit-learn `make_classification` (n = 6000, 10 features, 5
     informative, `flip_y` = 0.1, `class_sep` = 0.8, seeded), with a known mechanism.
  2. `breast_cancer`: Breast Cancer Wisconsin (Diagnostic), bundled with scikit-learn (569
     rows). Source: UCI ML Repository, DOI 10.24432/C5DW2B, CC BY 4.0. The positive event is
     **malignant** (scikit-learn target 0), declared explicitly. The test set is about 142 rows,
     so wide variability is expected.
  3. `adult` (opt-in, `--with-adult`, downloads from OpenML data_id 1590): UCI Adult, DOI
     10.24432/C5XW20, CC BY 4.0. The positive event is income `>50K`. Categorical features are one-hot
     encoded and numeric features standardised, both fitted on training rows only.
* Seeds 1–20 (Adult: seeds 1–10 to bound compute).

## Reporting rules

* Every scheduled run is reported, including failures (with the error message).
* Summaries give the mean, standard deviation, min and max of each difference, and the
  number of runs where the method was worse than raw.
* A negative or null result stays in the summary as it is.
* Sample sizes, seeds, library versions, hardware and wall-clock time are recorded.
* The results describe these scenarios only. They are not evidence of general superiority.
